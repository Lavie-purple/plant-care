# 个人植物管理与养护助手

Local-first 的个人植物管理工具。**结合植物档案、历史浇水记录和当地天气，判断今天该处理哪几盆。**

数据全部存在你自己的浏览器里，没有账号、没有云端、没有服务器同步。换设备通过导出/导入迁移。

---

## 它解决什么

不是浇水闹钟，而是**判断**：

- 记不住上次什么时候浇水 → 打开就知道，还给出依据
- 植物多，不知道今天处理谁 → 首页按建议类型分批，12 盆压成 3 次决策
- 天气变了，不知道该不该改计划 → 系统给建议，但**绝不自动改你的设置**，改不改你说了算
- 资料照片散落 → 档案、成长时间线、事件记录都在一处

## 三条硬规矩

这套设计里最不能妥协的三条：

1. **提醒的语义是「检查是否需要浇水」，不是「该浇水了」。** 天气不可用时明确降级并说明依据。
2. **系统永远不擅自改写你设定的养护周期。** 算出来不一样只会问你一次；你说保持就保持。
3. **每条建议都能追溯到具体数据。** 没有来源的判断不允许显示，界面上会写清「来源：浇水记录 09-21 14:20 · 实测」。

## 功能

| | |
|---|---|
| 今日养护 | 按建议类型分批，批量浇完可稍后补全 |
| 植物详情 | 今日建议 + 浇水记录 + 成长时间线 + 统计 |
| 我的植物 | 卡片 / 照片墙 / 列表三种浏览，九维筛选 |
| 记事件 | 14 种类型（施肥、换盆、修剪、开花、病虫害…），表单按类型变形 |
| 补录队列 | 批量记录超过 14 天未补全自动归入历史空白 |
| 规则冲突 | 系统算的周期和你设的不一致时，问一次 |
| 导出导入 | ZIP 打包，含照片。手机端可用 |
| 离线 | 装成 PWA，断网可用 |

## 技术栈

TypeScript · Vite 6 · React 19 · IndexedDB · 零 UI 框架依赖

```
src/
  domain/types.ts       领域类型，三条不变量在类型层强制
  engine/               推荐引擎：纯函数，零网络，零 AI
  storage/              IndexedDB + 多窗口乐观锁
  weather/              WeatherProvider 抽象 + 两个实现
  data/                 导入导出、ZIP、图片压缩、离线策略
  app/                  用例层：分组、统计、筛选、校验
  ui/                   界面层
```

**推荐引擎是纯函数**：不发网络请求、不读系统时钟、不调用 AI。
所有外部输入靠参数传入，因此完全可测试——405 个测试，其中一半是为了证明
断言真的会变红（见 `tests/MUTATION.md`）。

## 开发

```bash
npm install
npm run dev        # 开发服务器
npm run verify     # 类型检查 + 全部测试，全绿时打印 VERDICT: ALL GREEN
```

## 部署

推送后 GitHub Actions 自动构建并部署到 Pages。
部署前会跑一遍产物校验（资源路径、manifest、SPA 回退、天气接口不被缓存），
把「打开是白屏」这类问题挡在部署之前。

## 隐私

照片、植物资料、浇水历史、位置都不上传第三方。
天气请求只发送接口自己必需的经纬度。数据在浏览器 IndexedDB 里，
清浏览器数据会丢失，所以请定期导出。
